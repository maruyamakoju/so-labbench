## 2. North Star の置き換え案

**旧**（8/13、事業枠）: 「日本の研究現場の実作業1つを、3万円級アームと公開モデルで自動化できるかの
公開実証——2027年2月中旬までに存在証明1本」。

この目標はヒアリングで実タスクを特定することが前提だった。その前提は外れている。
存在証明を1本作ることと、基礎研究として正しく測ることは、必要な作業が違う。

**新（案）**: **「低価格アームの模倣学習について、第三者が再実行できる測定を積む。
成果の単位はデモではなく測定で、否定的結果も同じ重みで公開する。」**

成立条件（反証可能）:
- 各測定が事前登録され、判定規則がデータを見る前に固定されている
- 生データ・手順・失敗・逸脱がすべて公開され、他人が同じ数字に到達できる
- 参照できる外部の数字（他人の公開結果、または自分の事前公開値）と比較されている
- ハードウェア総額 10 万円以下（これは維持する。証拠層としての意味がここにある）

「2027年2月中旬」という期限は、外部イベント（ワークショップ・申請）に紐づくなら残す価値がある。
紐づかないなら外す。**期限が何のためにあるかを書けないなら、それは期限ではなく不安。**

## 3. 4 つの筋（依存順）

### 筋1: 公開方策は別のリグで動くか（= RQ-P1、実行中）

いま登録済みのもの。ACT と SmolVLA を各 30 試行、公開値との差。
**この分野で誰もやっていない種類の仕事**——公開結果は自己申告で、独立再現の報告がない。

### 筋2: 動かないなら、どの差分が効いているか（RQ-P1 の結果次第）

RQ-P1 で両方策が落ちた場合の次の一手。差分を1つずつ埋めて成功率が戻る点を探す。
**順番は当てずっぽうではなく `rig_sensitivity.csv` の感度順**（これが一晩の GPU 実験の使いどころ）。
成果物は「低価格アームの方策を他人が動かすときの移植チェックリスト」。

候補の差分: 前カメラのアスペクト、カメラ位置の残差、物体の見た目、照明、較正。

### 筋3: 正規化された関節指令はアーム間で移植できるのか（単独で成立、アーム1台で可能）

RQ-P1 の準備中に見つけた所見。SO-101 の行動は「そのアームの較正レンジに対する割合」で、
較正手順は `lerobot-calibrate` が操作者にどこまで動かさせたかで決まる。
ベンチマークのデモはグリッパーを最大 48.4 までしか開けず、我々のデモは 85.7〜100 を使っていた。

**アーム1台で示せる**: グリッパーを全可動域で較正 → 指令 40 の開き幅を測る → 意図的に狭い
レンジで再較正 → 同じ指令 40 の開き幅を測る。同じ数字が別の物理位置になることを直接示せる。
そのうえで「方策を公開するときは較正手順も公開しなければ意味が閉じない」と言える。

規模は小さいが、**LeRobot エコシステム全体に効く指摘**で、実験は1時間で終わる。
RQ-P1 の門 0 でどのみち測るので、ついでに取れる。

### 筋4: flow matching 方策の出力ゆらぎは、実機の失敗を説明するか（GPU のみで着手可能）

同じフレーム・同じ入力で SmolVLA を2回呼ぶと、出力が最大 3.2 単位ずれる（ACT は 0.000000）。
これは**1フレーム分の自然な動き（1〜2単位）より大きい**。

公開値では SmolVLA は offline の当てはまりが ACT より良いのに実機成功率は 1/3（0.23 対 0.63）。
この乖離は 8/13 の自前監査でも出ていた。ゆらぎがその一因かは測れる:

- offline: チャンクを通してゆらぎがどう蓄積するか、閉じ判断が何割のフレームで反転するか
  （`rig_sensitivity.py` の `resample` 行が既に測っている）
- 実機: 種を固定した SmolVLA と固定しない SmolVLA で成功率を比べる（各 n=30）

**種を固定すれば良くなるなら、それは誰でも使える改善**である。ならないなら、ゆらぎは
原因ではないと分かる。どちらでも報告できる。

## 3.5 検証して閉じた分岐: この方策はそもそも視覚を使っているのか

一晩の感度実験で予想外だったこと: **カメラの手合わせ誤差は全て床以下**だった。80px の平行移動も
5° の回転も ±10% のズームも、出力を「1フレーム分の自然な動き」ほども動かさない。

そこで疑った: **関節角から定型軌道を再生しているだけではないか。** この課題のデモ50本は同じ
ホーム姿勢から始まり物体の位置も狭い範囲なので、関節角だけで「軌道のどこにいるか」がほぼ決まる。
もしそうなら「ACT が 0.63」は学習された操作の証拠としては見た目より弱く、RQ-P1 も視覚的一般化
ではなく**2台の関節座標系が一致しているか**を測る実験になってしまう。

**2つの独立した測定で棄却した。**

1. **物体位置と成功の関係**（`finding_success_vs_position.md`）: 公開ロールアウト51本で、
   ACT は成功のほうがデモ中心に 13.6px 近い（区間はゼロを跨ぐ）、SmolVLA は逆に 14.8px 遠い。
   符号が逆でどちらも小さい。定型軌道の再生なら位置依存が出るはずで、出ていない。
2. **視覚アブレーション**（`finding_rig_sensitivity.md`）: 3台まとめて潰すと ACT の出力は
   自然変動の **20.6倍** 動く。1台ずつなら 2.6〜4.9倍で、その和より 1.9 倍大きい。
   **視覚を強く使っているが、視点間に冗長性がある**——1台失っても残り2台で補うので、
   1台ずつの摂動が小さく見えていた。

**RQ-P1 は当初の設計のまま成立する。** 加えて当日の優先順位が変わった: 正確に狙うことより
**3台とも在って合焦していること**がはるかに重要（位置は床以下、ぼけは2.4倍、1台欠落は
2.6〜4.9倍、全欠落は20倍）。index の取り違えで1台が黒いまま回すのが最悪の失敗モードで、
`preflight_rqp1.ps1` がそれを止める。

**副産物**: 検定1の過程で、公開されている成功率は**学習時より狭い位置条件で測られている**ことが
分かった（ロールアウトの水平ばらつき 227px 対 デモ 421px）。公開値を引用するときはその範囲ごと
引用すべきで、これは RQ1 を解凍して位置条件（C1）を測る価値を裏づける。

## 4. 順番と、やらないこと

```
いま ─ 筋1 (RQ-P1, 機材待ち) ─┬─ 移植する  → 筋4 (ゆらぎ) → RQ1 を解凍（動く方策ができたので）
                              └─ 移植しない → 筋2 (差分の切り分け)
      筋3 (較正の移植性) は門0のついでに取れるので並行
```

**やらないこと**（前の枠組みから引き継ぐ規律）:
- 自前デモを主語にした新しい実験。リモコンタスクは閉じた
- ボトルネックを特定する前のハード購入
- 結果を見てから判定規則を変えること
- 「うまくいかなかったので公開しない」

**外部**は顧客ではなく、査読者と再現者。具体的には ArmnetBench 作者への結果送付、
外部レビュアーへの依頼、note / Hugging Face / GitHub への公開。
この枠組みでは**ヒアリングは前提条件ではない**ので、クリティカルパスから外す。
