# RQ-P1: ArmnetBench の独立再現 — 別個体・別部屋の SO-101 で公開方策はどれだけ動くか（事前登録ドラフト）

作成: 2026-09-12 / 更新: 2026-09-13 / 状態: **登録準備完了。手首カメラ到着後、カメラ index を確定して位置合わせを記録した時点で「登録」に切り替える。** それまで指標・判定規則は変更しない。
根拠資料: `public_assets_track_design.md`、`armnetbench/reference_results.csv`、`armnetbench/frames/`。

## Research Question

ArmnetBench v0.1（Armnet、Apache 2.0）は SO-101 の8課題について、7方策の実機成功率を人手判定付きで公開している。
**同じ公開checkpointを、ベンチマーク作成者とは別の個体・別の部屋・別のカメラ個体の SO-101 で走らせたとき、成功率はどれだけ保たれるか。**
これは「低価格アームの公開結果は他人のリグで再現するか」という、コミュニティが暗黙に前提しているが誰も測っていない問いである。

## 仮説（事前登録）

- H-P1a: 成功率は落ちる。落ち幅は方策によって異なり、事前学習済みの視覚言語表現を持つ SmolVLA は ACT より落ち幅（比率）が小さい。公開値は ACT 0.63 / SmolVLA 0.23 なので、絶対値ではなく **公開値に対する比** で比べる。
- H-P1b: 落ち幅の大部分はカメラ配置の差で説明できる（RQ1のH1と同じ主張）。カメラを参照デモの画角に合わせた場合と、意図的に5cmずらした場合の差で検証する（副実験）。

## 課題と方策

- **主課題: eye_drops_to_basket**（"Put the eye drops into the basket"）。公開成功率: ACT 0.63 / Diffusion 0.43 / SmolVLA 0.23 / π0 0.70 / π0.5 0.67（各30本）。
- 副課題（機材が共通なら）: ring_insert。
- 方策: **第1段は ACT / SmolVLA の2つ**（手元の lerobot 0.5.1 でそのまま推論できることを確認済み）。Diffusion は 0.6 系への更新後に追加（0.5.1 は混在画像サイズを拒否）。π0 / π0.5 は公開checkpointが openpi（JAX）形式で lerobot では読めず、GR00T / MolmoAct も別ランタイムのため除外し、そう明記する。7方策中2方策の再現である点は結果の限界として先頭に書く。
- **微調整はしない。** 公開checkpointをそのまま使う（再現が問いなので）。

## 測定系

- 手元のアーム（SO-101、白Follower）に **front / top / wrist の3カメラ**。名前をベンチマークと同一にする。
- カメラ配置は参照デモの画像（`armnetbench/frames/`）を基準に `align_camera.py` 方式で合わせ、**残差を全試行に記録**（門にしない）。
- 制御周期は 20 fps（ベンチマークと同じ）。実効レートは RQ1 と同じく試行ごとに実測して記録。
- 露光固定、照明・背景（段ボール囲い）・マットを参照デモに寄せ、写真で記録。参照フレーム（ep0 先頭）の平均明るさは front 113 / top 108 / wrist 118（0〜255）。`lock_exposure.py --measure` の brightness 列をこれに最も近づける露光値を選ぶ（RQ0 では自分の学習データの約60に合わせた。今回はベンチマーク側に合わせる）。
- **カメラの既知の差分（2026-09-13、3台を実測して確定）**:

  | | 我々 | ベンチマーク | 差 |
  |---|---|---|---|
  | 前 | スマホ 1280×720 @20（16:9） | Pi Camera 3 1024×576（16:9） | アスペクト一致、画素とレンズが違う。**遅延未測定** |
  | 上 | C270 640×480 @20（**4:3**） | Pi Camera 3 1024×576（16:9） | **アスペクトが違う唯一のカメラ**。C270 は 1024×576 で 10fps、720p で 7.3fps しか出ない |
  | 手首 | InnoMaker U20CAM-1080P **1024×576** @20（16:9） | Innomaker U20CAM 1280×720（16:9） | **同機種**。720p は 10fps 上限（露光ではなくセンサー側、実測）なので 1024×576 を採る。アスペクト一致、画素 0.8 倍 |

  4:3 の逸脱は意図的に**上カメラ**へ置いた。夜間の感度実験で ACT は手首、SmolVLA は前カメラに
  最も依存すると分かっており、どちらも最重視しないカメラに逸脱を寄せるのが筋のため。
- 物体: 市販の目薬の紙箱（青系）、透明プラスチックかご、白い台。寸法を測って記録。**完全一致は不可能なので、差分を記録して結果と共に公開する。**

## 試行設計

- 各方策 **n=30**（ベンチマークと同数）、2方策で60試行（Diffusion 追加時は90）。1試行45秒上限＋リセット20秒で約1.1時間。
- 方策の順序は RQ1 と同じ巡回（`run_interleaved.ps1` の N アーム版）、開始位置 P1〜P5 を各方策6回ずつ。
- **開始位置 P1〜P5（参照デモ50本の初期状態から導出、`armnetbench/start_positions_P1-P5.csv`）**: top カメラの初期フレームで目薬の箱を色検出し（45/50本で検出）、重心を5クラスタに分けた。各クラスタの代表エピソードの top / front 画像が `armnetbench/frames/start_P*_{top,front}_ep*.jpg`。**当日はこの画像に合わせて箱を置く**（画素座標ではなく見た目で合わせ、差分は写真で残す）。

| 位置 | 参照本数 | 代表 | 置き方 |
|---|---|---|---|
| P1 | 8 | ep15 | 台の左・奥寄り、寝かせて斜め |
| P2 | 16 | ep44 | 台の中央、寝かせて横向き（最頻） |
| P3 | 5 | ep20 | 台の右・手前寄り、寝かせて45° |
| P4 | 7 | ep0 | 台の中央、**立てる** |
| P5 | 9 | ep10 | 台の右、寝かせて斜め |

  かごは常にアームの左（参照デモで不変）。
- 判定はベンチマークと同じ**人手3値**（成功 / 失敗 / 準最適）。成功のみを1と数える。
- **盲検**（`blind_review.py prepare`）: 試行をシャッフルして `R001` … に振り直し、動画をその名前で
  コピーし、判定シートには review_id しか書かない。対応表は別ファイルで、一度書いたら振り直せない
  （ラベルを見てから割り当てを選べないようにするため）。**ArmnetBench の判定者は方策を見ながら
  自分の試行を判定している**ので、ここは参照実装より我々のほうが強い。差分として記録する。
- 集計は `harness/rqp1_results.py`（成功率・Wilson CI・公開値との差 Δ。盲検かどうかも出力に書く）。
- 除外規則は RQ1 v1.2 の `invalid_trial` と同じ。

## 既知の障害と、その扱い（全文は `rqp1_design_review.md`）

| # | 事項 | 扱い |
|---|---|---|
| A1 | **正規化された関節値はアーム間で移植できない。** 方策の「開け」は平均 34.4・最大 48.4 で、我々のデモは 85.7〜100 を使っていた。同じ数字が別のアームでは別の物理位置になる | 当日の手順 0 で物理確認。通らなければ実験は成立しない。**これ自体が公開に値する所見** |
| A2 | 我々の閾値 `CLOSE_T=40` は彼らのデータの 95% を「閉」と誤判定する | `labbench_config_rqp1.json` で **15.0** に（彼らのデモの二値クラスタ中点 18.0 から導出、根拠ごと記載） |
| A3 | 方策の失敗と舞台の不一致を切り分けられない | 当日の手順 3、人手デモのオープンループ再生 |
| B1 | 物体が別物（同型の目薬の箱・別のかご・別の台） | 寸法と写真で記録。**offline では模擬できない最大の未測定要因** |
| B8 | ベンチマーク側の打ち切り時間が方策ごとに違う（ACT の失敗 44.5s 対 SmolVLA 24.1s） | 我々は両方 45 秒。成功は中央値 7〜9 秒で、全8課題 515 本の成功試行のうち 45 秒超は 0%。SmolVLA には参照より有利な条件である点を明記 |

## 検出力（データを見る前に確定）

n=30 対 n=30 の二項比較。**参照値も n=30 なので、我々が試行を増やしても不確かさに床がある。**

| 我々の n | 差の標準誤差 | 80%の検出力で見える差 |
|---|---|---|
| 30 | 0.125 | **35 ポイント** |
| 60 | 0.108 | 30 ポイント |
| ∞ | 0.088 | 25 ポイント |

この設計は「そもそも移植できるのか」を見るためのもので、中程度の劣化を精密に測るものではない。
n を 60 にしても買えるのは 5 ポイントで実機時間は倍になるので **n=30 で行く**。
**「解像しない」を「差がない」と書かない**ことのほうが重要。

## 指標（事前固定）

1. 主指標: 方策ごとの成功率と、公開値との差 Δ = 成功率(本リグ) − 成功率(ArmnetBench)。Wilson 95% CI を併記。
2. 副指標: 失敗の分類（approach / grasp / transport / place / instability）を動画から人手で付ける。
3. 探索的: カメラ残差・実効レートと成功の関係。参照デモに対する offline 予測誤差（GPUのみ、事前に取得）。

## 判定規則（データを見る前に固定）

n=30 対 n=30 で 80% の検出力があるのは 35pt の差。

| 結果 | 解釈 | 次 |
|---|---|---|
| 両方策で Δ が ±35pt 以内 | 公開結果は別リグで再現する。低価格アームの結果は「そのリグ限り」ではない | 報告・公開し、ArmnetBench 作者へ送る |
| 片方だけ大きく落ちる | 方策依存のリグ感受性 | 落ちた方の失敗分類と `rig_sensitivity.csv` の感度を突き合わせる |
| 両方 0 付近、**手順3のリプレイは成功** | 舞台は互換なのに方策が動かない。移植性の否定的結果 | 感度の高い差分から1つずつ潰す第2実験 |
| 両方 0 付近、**リプレイも失敗** | 実験になっていない。方策の話として報告してはいけない | リグを直してやり直す |
| 我々のほうが高い | 35pt 以内は区別できないので解釈しない | 再現性の観点ではむしろ良い報せとして記録 |

**どの枝でも公開する。** 「うまくいかなかったので出さない」は、この研究の存在理由（証拠層）を
自分で壊す。

## 公開

結果の正負にかかわらず、試行動画・残差ログ・物体寸法・カメラ配置写真・判定表を公開する。ArmnetBench の作成者に結果を送る（外部レビュー）。

## 当日の手順

**手順 0 と 3 を飛ばさないこと。** どちらも「方策が一般化しない」と「そもそも物理的に不可能」を
切り分けるための門で、飛ばすと 60 試行が解釈不能になる。

0. **グリッパーが足りるか** — `python gripper_check.py`。方策は平均 34.4・最大 48.4 しか開けと
   言わない（我々の自前デモは 85.7〜100）。**34.4 での開き幅を定規で測り、物体の幅 +4mm 以上**を
   確認する。足りなければ薄い箱に替え、両方の寸法を記録する。
1. `preflight_rqp1.ps1` → 全 OK。カメラ index は `lerobot-find-cameras opencv` で確定して
   `labbench_config_rqp1.json` に反映。前カメラの露光は参照フレームの明るさ（front 113）に合わせる。
2. 3カメラの位置合わせ（`ALIGN_CAM_INDEX` を切り替えて `align_camera.py watch <基準画像>`）。残差は自動記録。
3. **舞台の幾何が互換か** — 人手デモをオープンループで3本再生する。

   ```
   lerobot-replay.exe --robot.type=so101_follower --robot.port=<port> --robot.id=<robot id>
                      --dataset.repo_id=pravsels/object_top_shelf_reset_remote --dataset.episode=0
   ```

   **1本目は手を 12V スイッチに置いて実行する**（関節レンジの差で可動域外へ行く可能性がある）。
   目薬がかごに入れば舞台は互換で、以後の失敗は方策に帰属できる。入らなければ物体位置か据え付けが
   ずれており、方策を走らせても何も分からない。
4. 舞台の写真（前・上・手首）と物体の寸法を `armnetbench/rig_photos/` へ。
5. `run_interleaved.ps1 -Study rqp1 -Condition eyedrops -Pairs 30 -Arms act,smolvla -DryRun` → 本番（約70分）。
6. `finish_condition.ps1 -Study rqp1 -Condition eyedrops -Pairs 30 -Models act,smolvla`
7. **盲検判定** — `python blind_review.py prepare rqp1 eyedrops` → `review/rqp1_eyedrops/` の動画を見て
   `rqp1_eyedrops_labels.md` に1語ずつ → `python blind_review.py check rqp1 eyedrops` →
   `python rqp1_results.py eyedrops`。**60試行が終わるまで採点も集計も見ない。**
