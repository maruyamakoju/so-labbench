# 所見: SmolVLA は関節状態で動き、ACT はカメラで動く。ただし ACT の一部は例外

2026-09-14〜15 / 事前登録: `prereg_input_attribution.md`（測定前に公開、GitHub の時刻 21:09:55）
公開 checkpoint と公開データのみ、実機不要 / `armnetbench/input_attribution.py` → `armnetbench/attribution/*.csv`
判定: `armnetbench/judge_input_attribution.py`（事前登録の規則をそのままコード化）
検算: `test_input_attribution.py`（49項目）、`mutation_check.py`（全体43通り、判定規則だけで16通り、全部検出）

## 問い

`finding_vision_reliance_act_vs_smolvla.md` で、全カメラを黒にしても SmolVLA の指令は人手デモの
ばらつきの 9〜17% しか動かないと分かった（ACT は 82〜132%）。方策の入力は画像・関節状態・指示文の
3種類しかない。**1つずつ取り除いて、同じフレーム・同じ種で、指令がどれだけ動くかを比べた。**
8課題 × 2方策、stride 50、計 2,607 フレーム。

## 事前登録の判定（登録どおり、書き換えなし）

| | 仮説 | 結果 | 判定 |
|---|---|---|---|
| 有効性 | `identity` が全方策・全課題で厳密に 0 | 0 | **有効** |
| 配線 | ACT は指示文を変えても厳密に 0（追記1で測定前に追加） | 0 | 合格 |
| H4 | 状態の押しを倍にすると指令がもっと動く（両方策） | ACT 8/8、SmolVLA 8/8 | 支持（**ただし下の注意**） |
| **H1** | SmolVLA は視覚を失うより自己受容を失うほうが動く | **8/8** | **支持** |
| **H2** | SmolVLA の指示文の効果は自己ノイズの2倍未満 | **0/8** | **支持されない** |
| **H3** | ACT は自己受容を失うより視覚を失うほうが動く | **8/8** | **支持** |

閾値はすべて 8課題中7。

## 結果1: SmolVLA の指令は、関節状態を失うとカメラを失うより5〜9倍大きく動く

人手デモの行動のばらつきに対する%:

| 課題 | カメラ全部黒 | 状態を平均に置換 | 比 |
|---|---|---|---|
| cable_clip | 8.8 | 76.7 | **8.8倍** |
| cable_unclip | 12.5 | 84.7 | 6.8 |
| tool_insert | 12.3 | 77.1 | 6.3 |
| tool_removal | 13.7 | 82.0 | 6.0 |
| eye_drops_to_basket | 14.2 | 80.8 | 5.7 |
| block_stack | 14.2 | 79.3 | 5.6 |
| ring_insert | 15.0 | 78.9 | 5.3 |
| eye_drops_to_shelf | 14.8 | 74.3 | **5.0** |

**8課題すべて、5.0〜8.8倍。** 状態を平均で置き換えると、SmolVLA の指令は人手デモのばらつきの
74〜85% 動く。**これは ACT が視覚を失ったときの動き（83〜130%）とほぼ同じ大きさである。**

この比較は視覚に有利に偏っている（事前登録に明記）。黒い画像は学習分布から大きく外れるが、
平均の関節状態は分布の中にある。**不利な比較で状態が5倍以上勝っている**ので、控えめな結論である。

装置も効いている。状態に加える雑音を 0.5σ から 1σ に倍にすると、SmolVLA の指令の動きは
25〜34% から 49〜62% へ、**8課題すべてで 1.8〜2.0倍になる。**

## 結果2: ACT は8課題すべてでカメラに頼る。関節状態は、6課題では実質使っていない

| 課題 | カメラ全部黒 | 状態を平均に置換 |
|---|---|---|
| tool_insert | 129.6 | 0.1 |
| cable_unclip | 105.5 | 0.1 |
| eye_drops_to_basket | 95.3 | **0.0** |
| eye_drops_to_shelf | 91.1 | **0.0** |
| block_stack | 90.7 | 1.1 |
| tool_removal | 82.8 | 0.3 |
| **cable_clip** | 87.6 | **40.6** |
| **ring_insert** | 84.1 | **36.0** |

H3 は 8/8 で支持。ただし中身は2種類に分かれる。

- **6課題**: 関節状態を平均で置き換えても、指令はばらつきの 1.1% 以下しか動かない。
  状態はモデルの入力まで届いている（配線検査で、全関節 +100 で正規化後の状態が約1から約6に変わる
  ことを確認）ので、**届いた状態を使っていない。**
- **cable_clip と ring_insert**: 36〜41% 動く。**状態をはっきり使っている。**

**設定の違いでは説明できない。** 8つの ACT checkpoint は同じ作者の同じ設定（VAE あり、chunk 30、
dim 512、encoder 4 層、ResNet-18、lr 1e-5、kl_weight 10）で、違うのは学習ステップ数だけ
（10,000 が6つ、30,000 が2つ）。そして状態を使う2課題はどちらも 10,000 で、状態を使わない課題にも
10,000 が4つある。**同じ手順で学習した ACT が、課題によって状態を使ったり使わなかったりする。**
理由はここでは分からない。

### 私が昨夜書きかけて外した一般化

事前登録の後、1フレームの配線検査（eye_drops_to_basket）で ACT が状態にほとんど反応しないのを見て、
ユーザーへの報告に「**ACT は関節状態を無視しているように見える**」と書いた（1フレームなので判定では
ないと添えて）。**8課題では 6/8 だった。** 検査に使った課題が、たまたま無視する側だった。
今日だけで同じ種類の一般化の訂正は4回目になる。

## 結果3: H2 は外れた。SmolVLA は一定の指示文で微調整されても、指示文で動く

**予測**: 各 checkpoint は1つの課題で毎回同じ指示文を与えて微調整されているので、指示文は情報を
運ばず、使わないことを学ぶはず。

**結果**: 8課題すべてで外れた。

| | 自己ノイズの何倍 | ばらつきの% |
|---|---|---|
| 指示文を空にする（`task_blank`） | **3.0〜6.4倍** | 5.8〜12.5% |
| 別の課題の指示文にする（`task_other`） | 1.2〜4.8倍 | 2.0〜9.2% |
| （参考）自己ノイズ | 1倍 | 1.5〜2.7% |

判定規則は2つの摂動の**両方**が2倍未満であることを求めていて、`task_blank` は全課題で3倍を超えた。
**判定は「支持されない」。**

効果の大きさを並べておく。判定を和らげるためではなく、読者が大きさを取り違えないためである。
指示文を空にしたときの動きは、同じ課題で関節状態を失ったときの 7〜15%（7分の1から14分の1）で、
カメラを全部失ったとき（9〜15%）と同程度である。**SmolVLA は指示文を使っている。関節状態ほどでは
ないが、カメラと同じくらいには。**

**事後の観察（判定ではない）**: 空の指示文は、別の課題の実在する指示文より大きく動かす
（8課題すべてで同じか上、eye_drops_to_shelf はほぼ同点）。**どの課題を言っているかより、
文があること自体が効いている**ように見える。これは登録していない比較で、検定もしていない。

## H4 の欠陥は、実際に現れた

事前登録の追記2（本番前）で、H4 は「装置が壊れている」と「方策が入力を無視している」を区別できないと
書いた。**それが起きた。** ACT は H4 を 8/8 で通ったが、状態を使わない6課題では、倍の押しで指令が
動いた量はばらつきの **1.0% 以下**である。

| ACT、状態を使わない6課題 | 0.5σ の押し | 1σ の押し |
|---|---|---|
| ばらつきの% | 0.0〜0.6 | 0.0〜1.0 |

H4 はこれを「倍にしたらもっと動いた」と数えている。**この6課題について、H4 の「支持」は装置が
効いている証拠にならない。** 装置が状態を届けていることは、別の2つの証拠で確かめている——
正規化後の入力テンソルが変わること、そして SmolVLA で同じ押しが倍の応答を生むこと。
登録規則はそのまま適用し、H1・H3 を解釈した。その判定は変えていない。

## 2つの所見がつながる: SmolVLA は較正の不一致に最もさらされる

`finding_calibration_portability.md` で、LeRobot の関節値は**そのアームの較正レンジに対する%**で、
公開 SO-101 データはアーム間で尺度を共有していないと示した。**別のアームで方策を動かすと、
関節状態の値そのものがずれる。**

今回、SmolVLA の指令は関節状態を失うと 74〜85% 動くと分かった。ACT は6課題で 1% 以下。
**したがって、他人のアームで公開 checkpoint を動かしたときに較正のずれを最も強く受けるのは SmolVLA
で、ACT はほとんどの課題で受けにくい、と予測できる。**

**これは予測であって結果ではない。** 較正のずれは「平均への置換」とは違う種類の摂動で、ここでは
測っていない。公開データだけで測れる（次の実験の候補）。

## 何が言えて、何が言えないか

**言える**:
- 公開 checkpoint の SmolVLA は、8課題すべてで、関節状態を取り除くとカメラを取り除くより5〜9倍大きく
  指令が動く。視覚に有利な比較でこの差である。
- 公開 checkpoint の ACT は、8課題すべてでカメラを取り除くほうが大きく動く。関節状態は6課題で実質
  使っておらず、2課題ではっきり使っている。同じ設定での違いで、理由は分からない。
- SmolVLA は、一定の指示文で微調整されているにもかかわらず、指示文を空にすると自己ノイズの3〜6倍動く。

**言えない**:
- **「使っている」の意味は、取り除いたときに指令が動くことに限る。** 教師強制の単ステップ予測であり、
  閉ループのロールアウトで何が起きるかではない。
- **SmolVLA が「軌道を再生しているだけ」だとは言えない。** 関節状態に強く依存することは、見ていない
  ことを意味しない（カメラを全部黒にした効果は、8課題で自己ノイズの 4.3〜9.1倍ある）。ただし、ACT について
  `finding_success_vs_position.md` で棄却した「定型軌道の再生」仮説を、**SmolVLA については改めて
  問う理由**にはなる。
- VLA は1つ、非 VLA は1つ。アーキテクチャと学習手順は分けられない。
- ACT の2課題がなぜ状態を使うのか。
