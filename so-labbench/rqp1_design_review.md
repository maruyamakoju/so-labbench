# RQ-P1 設計レビュー（反証的プレモーテム）

作成: 2026-09-13 未明 / 対象: `rqp1_armnetbench_reproduction_protocol.md`
目的: **実機を動かす前に、この実験が失敗する道筋を先に全部書き出す。** データを見た後に言い訳を
考えるのではなく、見る前に「何が起きたらこう解釈する」を固定するため。

以下、(A) 実機前に潰すべき欠陥、(B) 潰せないが記録すべき差分、(C) 統計的な限界、
(D) 結果が出た後に取る行動、の順。**(A) は当日の作業手順に組み込み済み。**

---

## A. 実機を動かす前に潰す（発見済み・対策済み）

### A1. グリッパーの正規化値はアーム間で移植できない ★最大のリスク

SO-101 の関節値は `lerobot-calibrate` が記録した **そのアームの可動域に対する割合**で、
物理的な角度ではない。ベンチマークの方策はベンチマークのアームの目盛りで出力する。

実測（`pravsels/object_top_shelf_reset_remote` 50本、3043フレーム）:

| | 閉 | 開 | 境界 |
|---|---|---|---|
| ベンチマーク | 平均 1.6（p95 = 7.9） | 平均 34.4、最大 48.4 | 18.0 |
| 我々の学習データ | 平均 29.0 | 平均 85.7、最大 100 | 57.3 |

**彼らのテレオペは正規化レンジの下半分しか使っていない。** 我々のグリッパーは全可動域
1062 tick で較正済みなので、方策が「開け」と言う 34〜48 は我々のアームでは
**365〜510 tick、全開の 1/3〜1/2** にしかならない。我々自身のデモが使った開き（910〜1062 tick）
の半分以下。

**帰結**: 物体の幅より狭ければ、方策は一般化以前に物理的に掴めない。全試行が失敗し、
その原因は方策ではなく較正になる。

**対策（当日、必須）**: `gripper_check.py` でグリッパーを 0 / 15 / 34 / 48 に動かして
開き幅を測り、**物体の幅 + 4mm 以上あることを確認してから**物体を確定する。足りなければ
薄い箱に替え、寸法を差分として記録する。

**これ自体が発表に値する所見**: 低価格アームの公開方策を他人が動かす際、較正手順を揃えないと
指令値の意味がずれる。ArmnetBench の README に較正手順の記載はない。

### A2. 我々の閾値をそのまま当てると採点が壊れる

`CLOSE_T = 40` は我々のアームの目盛り。彼らのデータに当てると **95% のフレームが「閉」**
になる。主指標は人手判定なので影響しないが、副指標（採点器の taxonomy）は無意味になる。

**対策済み**: `labbench_config_rqp1.json` の `grip_close_threshold` を **15.0** に。
導出は上表の二値クラスタリング中点 18.0 から、閉側 p95 = 7.9 に余裕を取った値。
設定ファイルに導出根拠ごと書いた。

### A3. 舞台の幾何が合っているかを、方策と切り離して確かめる手段がなかった

方策が失敗したとき、「方策が我々のリグに一般化しない」のか「物体の位置が違って誰にも掴めない」
のか区別できない。

**対策**: ベンチマークは人手デモの**行動軌跡そのもの**を公開している。60試行の前に
`lerobot-replay --dataset.repo_id=pravsels/object_top_shelf_reset_remote --dataset.episode=<n>`
で**成功デモを3本オープンループ再生**する。

- 目薬がかごに入る → 舞台の幾何はベンチマークと互換。以後の失敗は方策に帰属できる
- 入らない → 物体位置かアームの据え付けがずれている。**方策を走らせる意味がない**ので直す

これは protocol が「AIなしのscripted baseline」として要求していた項目そのもので、
ベンチマークの公開データのおかげで新規に作らずに済む。A1 の較正ずれもここで露見する。

### A4. 判定シートが盲検でなかった（私の設計ミス）

最初に作った `rqp1_human_labels.md` は各行に方策名が入っていた。判定者は自分で方策を選び、
どちらが勝つはずかの予想を持っている人間なので、これは結果に直結する。

**対策済み**: `blind_review.py prepare` が試行をシャッフルして `R001` … に振り直し、
動画を振り直した名前でコピーし、対応表は別ファイルに書いて「判定が終わるまで開かない」と
明記する。対応表は一度しか書かれない（ラベルを見てから振り直せない）。
なお **ArmnetBench の判定者は自分の試行を方策を見ながら判定している**ので、ここは参照実装より
我々のほうが強い。差分として記録する。

### B8 の詳細（参照値そのものの非対称性）

ベンチマークは「試行時間の上限を決めていない、打ち切りは操作者判断」と明記している。
失敗試行の長さを見ると、その判断が**方策ごとに違う**:

| 方策 | 失敗試行の長さ（中央値） | 成功試行の長さ（中央値） |
|---|---|---|
| ACT | 44.5 s | 7.0 s |
| SmolVLA | 24.1 s | 7.3 s |
| Diffusion | 21.0 s | 8.9 s |
| π0 | 20.8 s | 8.5 s |

**ACT は SmolVLA の約2倍の時間を与えられている。** 成功は中央値 7〜9 秒で起きるので
成功率への影響は小さいと考えられるが、公開値を比較対象に使う以上、この非対称性は明記する。

我々は両方策に 45 秒を与える。全8課題 515本の成功試行のうち 45 秒を超えたものは **0%**
（最長 38.5 秒）なので打ち切りによる取りこぼしはない。ACT には参照と同条件、
SmolVLA には参照より**有利**な条件になる。

## C. 統計的な限界（データを見る前に確定）

n=30 対 n=30 の二項比較。**参照値そのものが n=30 なので、我々が試行を増やしても不確かさに床がある。**

| 我々の n | 差の標準誤差 | 80% の検出力で見える差 |
|---|---|---|
| 30 | 0.125 | **35 ポイント** |
| 60 | 0.108 | 30 ポイント |
| ∞ | 0.088 | 25 ポイント |

**この設計は「そもそも移植できるのか」を見るためのもので、中程度の劣化を精密に測るものではない。**
ACT の公開値 0.63 に対し、我々が 0.30 なら検出できる。0.50 なら「解像しない」が正しい報告。

n を 60 に増やしても買えるのは 5 ポイントで、実機 1.1 時間が 2.2 時間になる。**n=30 で行く。**
「解像しない」という結果を「差がない」と書かないことのほうが重要。

覗き見の禁止: 60試行が終わるまで採点も集計も見ない。盲検判定を全部書き終えてから
`rqp1_results.py` を初めて走らせる。

## D. 結果が出た後に取る行動（先に固定）

| 観測 | 読み | 次 |
|---|---|---|
| 両方策が公開値の ±35pt 以内 | 公開結果は別リグで再現する。低価格アームの結果は「そのリグ限り」ではない | 報告して公開。ArmnetBench 作者へ送付 |
| 片方だけ大きく落ちる | 方策依存のリグ感受性 | 落ちた方の失敗分類と `rig_sensitivity` の感度を突き合わせる |
| 両方 0 付近、**A3 のリプレイは成功** | 舞台は互換なのに方策が動かない。移植性の否定的結果 | 一番感度の高い差分（`rig_sensitivity` の上位）から1つずつ潰す第2実験 |
| 両方 0 付近、**A3 のリプレイも失敗** | 実験になっていない。結果を方策の話として報告してはいけない | リグを直してやり直す |
| 我々のほうが**高い** | 解釈しない（n=30 では 35pt 以内は区別できない）。否定的結果として記録 | 再現性の観点ではむしろ良い報せとして報告 |

**どの枝でも公開する。** 「うまくいかなかったので出さない」は、この研究の存在理由（証拠層）を
自分で壊す。

## E. 私がまだ確かめていないこと（正直な残余）

- 我々のグリッパーが 48 で何 mm 開くか。**A1 の物理確認待ち。これが通らないと実験自体が成立しない。**
- リプレイがベンチマークの軌跡を我々のアームで安全に再生できるか（関節レンジの差で
  可動域外へ行かないか）。**1本目は手を電源スイッチに置いて実行すること。**
- スマホを上カメラにしたときの実効遅延。`rig_sensitivity` は遅延を模擬していない。
- 物体の差（B1）の寄与。これだけは offline で測る方法がない。
